# 모듈형 개인 관리 플랫폼 — 기능 명세서 (디자인 의뢰용)

> 목적: 디자이너가 시안 작업에 필요한 **기능·화면·상태**만 정의한다.
> 개발 언어, 프레임워크, 서버·배포 환경, API 규격은 범위 밖.
> **인증/로그인 없음** — 단일 사용자 기준. 앱을 열면 곧바로 대시보드.

---

## 1. 제품 정의

한 사람의 일상 데이터(일정, 할 일, 가계부, 서재, 기록 등)를 **하나의 껍데기(Shell) 안에서 여러 "모듈"로 조립해 쓰는 개인용 대시보드 플랫폼.**

핵심은 개별 모듈이 아니라 **모듈을 담는 그릇**이다. 모듈은 나중에 추가·삭제·교체되며, 서드파티가 만든 모듈도 들어온다. 따라서 디자인은 **"어떤 모듈이 들어와도 같은 옷을 입는 시스템"** 이어야 한다.

### 설계 원칙 (디자인 판단 기준)

| 원칙 | 의미 |
|---|---|
| 단일 시각 계약 | 모든 모듈은 공용 컴포넌트/토큰만 사용. 모듈이 자기만의 스타일을 들고 오지 않는다. |
| 껍데기 불변 | 사이드바·헤더·모달 레이어는 어떤 모듈에서도 동일하게 동작. |
| 사용자 커스터마이즈 | 색/폰트/모서리/배경/명암/언어를 사용자가 바꾼다. **시안은 한 가지 색에 의존하면 안 된다.** |
| 상태 우선 | 빈 상태·로딩·에러·오프라인이 정상 상태와 동급의 1급 화면. |

---

## 2. 핵심 개념 (용어 정의)

| 용어 | 정의 |
|---|---|
| **모듈(Module)** | 하나의 기능 영역. 자체 화면(들)과 아이콘, 카테고리, 이름, 설명을 가진다. 예: 캘린더, 할 일, 가계부. |
| **카테고리(Category)** | 모듈 묶음. 사이드바 그룹 제목이 된다. 예: 생산성, 금융, 설정. 사용자가 직접 추가/이름 변경 가능. |
| **위젯(Widget)** | 모듈이 대시보드에 내보내는 요약 카드. 한 모듈이 여러 개를 낸다. 예: 캘린더 → "미니 달력", "오늘의 일정". |
| **시스템 모듈** | 플랫폼 기본 제공, 삭제 불가. 대시보드, 모듈 관리, 개인화, 외부 서비스 키, 백업, 문서. |
| **외부 모듈** | 설치/제거 가능. 설치 후 사이드바와 대시보드에 자동 편입. |
| **모듈 간 연동** | 한 모듈이 다른 모듈의 데이터를 자기 화면에 끌어온다(§5-8). 상대 모듈이 없으면 조용히 사라진다. |

## 3. 화면 골격 (Shell)

모든 화면이 공유하는 뼈대. **이 골격 시안이 가장 중요한 산출물.**

```
┌──────────────┬──────────────────────────────────────────┐
│  사이드바     │  모듈 헤더 (제목 + 아이콘 + 액션)          │
│              ├──────────────────────────────────────────┤
│  - 검색       │                                          │
│  - 대시보드   │           모듈 콘텐츠 영역                 │
│  ──────────  │      (필요 시 내부 보조 사이드바)          │
│  [카테고리]   │                                          │
│   · 모듈 A    │                                          │
│   · 모듈 B    │                                    (FAB) │
│  ──────────  │                                          │
│  [설정 그룹]  │                                          │
└──────────────┴──────────────────────────────────────────┘
```

### 3-1. 사이드바

- 상태: **확장 / 축소(아이콘만) / 모바일 오버레이** 3종.
- 구성: 상단 브랜드 영역 → 검색 → 카테고리 제목 + 모듈 항목 리스트 → 구분선 → 설정 그룹.
- 모듈 항목: 아이콘 + 라벨 + (선택) 카운트 배지 + 활성 상태.
- **하위 항목**: 모듈이 내부 하위 메뉴를 가질 수 있다(접기/펼치기).
- **배너 슬롯**: 공지/알림 배너가 들어가는 자리 하나.
- 모듈 개수 가변(5개 ~ 40개+). **스크롤과 그룹 밀도**를 감안해 설계.

### 3-2. 모듈 헤더

- 모듈 아이콘 + 제목, 우측 액션 영역(검색, 뷰 전환, 필터, 더보기).
- 하위 페이지 진입 시 **뒤로가기 버튼** + 경로 표기.
- 탭형 모듈을 위한 **탭 바** 변형 필요.

### 3-3. 모듈 내부 보조 사이드바

모듈이 자기 화면 왼쪽에 **두 번째 사이드바**를 가질 수 있다(§5-3 참고).
→ 껍데기 사이드바 + 모듈 사이드바 + 콘텐츠의 **3단 레이아웃**이 성립해야 한다. 모바일에서는 모듈 사이드바가 서랍/필터 시트로 붕괴.

### 3-4. 공통 레이어

- **모달**: 중앙 모달, 확인(파괴적 행동) 모달, 이미지 뷰어 모달. **모달 위에 모달이 겹친다**(예: 스캔 모달 → 생성 모달).
- **FAB**: 모바일에서 주요 생성 액션.
- **컨텍스트 메뉴**: 우클릭/더보기 버튼 공용.
- **토스트**: 성공·경고·오류.
- **AI 표식**: AI를 쓰는 모달/버튼에 별도 표식이 붙는다(§5-6).

## 4. 시스템 모듈 명세

### 4-1. 대시보드

- 위젯을 **드래그·리사이즈로 배치하는 그리드**. 보기 모드 / 편집 모드 구분.
- 편집 모드: 위젯 추가 목록, 제거 버튼, 그리드 가이드, 저장/취소.
- 위젯 카드: 제목 + 아이콘 + 콘텐츠 + (선택) 해당 모듈로 이동.
- 위젯 크기 1×1 ~ 대형까지 가변. **같은 위젯이 크기별로 다르게 보이는 규칙** 필요.
- **삭제된 모듈의 위젯**: "찾을 수 없는 위젯" 대체 카드 상태 존재.
- 모바일: 그리드 → 1열 스택으로 붕괴.

### 4-2. 모듈 관리

- **모듈 목록**: 설치된 모듈 카드 리스트. 아이콘, 이름, 설명, 버전, 제작자, 카테고리, 활성 토글, 설정/제거.
- **설치 가능 모듈**: 설치 버튼, 진행 상태(진행 중 / 실패 / 완료).
- **카테고리 관리**: 추가·수정·삭제, 아이콘 선택, 정렬, **표시 이름의 다국어 키 편집**.
- 모듈은 필요한 **외부 서비스 키**를 선언 → 목록에 "필수 / 선택" 표시와 미충족 경고 배지.

### 4-3. 개인화 (Personalization)

사용자가 직접 조정하는 항목 — **시안은 이 조합들이 다 성립해야 한다.**

| 항목 | 옵션 |
|---|---|
| 테마 모드 | 라이트 / 다크 / 시스템 |
| 강조색 | 프리셋 팔레트 + 사용자 지정 색상 |
| 배경 명암·색온도 | 중성/따뜻함/차가움 등 배경 톤 조절 |
| 배경 이미지 | 없음 / 프리셋 / 업로드. 이미지 위에서도 가독성 유지 |
| 글꼴 | 글꼴 종류 선택 |
| 글자 크기 배율 | 축소 ~ 확대 슬라이더 |
| 모서리 둥글기 | 각짐 ~ 둥금 단계 |
| 언어 | 다국어 전환 (영/한/일/중 번체·간체/말레이 등) |

각 항목은 **선택지가 미리보기로 보이는 카드형 선택기**로 제공.

### 4-4. 외부 서비스 키 관리

- 키 목록(이름, 설명, 마스킹된 값, 등록 여부).
- 등록/수정 모달, 삭제 확인.
- **"이 키를 요구하는 모듈들" 목록 화면** — 모듈 카드 + 용도 설명 + 필수/선택 표시.
- 키 미등록 시 해당 모듈에 경고 상태 노출.

### 4-5. 백업

- 백업 생성 / 목록(생성 시각, 크기) / 다운로드 / 복원 / 삭제.
- 복원은 되돌릴 수 없음 → **강한 확인 모달**.

### 4-6. 문서

- 앱 내 사용 설명 뷰(문서 본문 타이포 — 제목 체계, 코드 블록, 표, 인용).

### 4-7. 설정 행(Row) 패턴

설정성 화면은 전부 **"라벨 + 설명 + 현재 값 + 액션"** 한 줄 패턴으로 조립된다. 이 행 컴포넌트 하나가 개인화·모듈 관리·키 관리 전부를 커버해야 한다.

## 5. 모듈 표준 명세 — 예시: 캘린더

> **이 절이 "모듈 하나의 표준 형태"다.** 새 모듈은 전부 이 틀을 따른다.
> 디자이너는 이 캘린더를 그리면, 사실상 모든 모듈의 뼈대를 그린 것.

### 5-0. 모듈이 선언하는 것 (모듈 명세서 = 모듈 카드에 그대로 표시됨)

| 항목 | 캘린더의 값 |
|---|---|
| 표시 이름 | 캘린더 |
| 아이콘 | 달력 아이콘 (단일 선형 아이콘 세트에서) |
| 카테고리 | 생산성 |
| 한 줄 설명 | "운명(또는 치과)과의 약속을 놓치지 마세요." — **설명은 유머가 섞인 한 문장**. 톤 참고 |
| 버전 / 제작자 | 0.0.5 / 개인 개발자 |
| 화면 | 메인 화면 1개 |
| 위젯 | 2개 — 미니 캘린더, 오늘의 이벤트 |
| 외부 서비스 키 | AI(선택), 지도(선택) — **없어도 동작하되 기능 일부 비활성** |
| 다국어 | 6개 언어 |

### 5-1. 메인 화면 레이아웃

```
┌──────────────┬───────────────────────────────────────────┐
│ [모듈 사이드바]│ 모듈 헤더: 캘린더            [+ 이벤트]    │
│              ├───────────────────────────────────────────┤
│  미니 달력    │  ◀ 2026년 7월 ▶   [오늘]   [월|주|일|일정표]│
│  ──────────  ├───────────────────────────────────────────┤
│  캘린더 목록  │                                           │
│   · 개인      │           캘린더 그리드                    │
│   · 회사      │      (이벤트 블록, 드래그로 이동/리사이즈)   │
│  ──────────  │                                           │
│  카테고리 목록 │                                           │
│   · 업무 🔴   │                                           │
│   · 약속 🟡   │                                     (FAB) │
└──────────────┴───────────────────────────────────────────┘
```

### 5-2. 뷰 전환 (4종)

| 뷰 | 요구 |
|---|---|
| **월** | 날짜 셀 그리드. 셀당 이벤트 N개 + "+3개 더". 오늘 강조. 이전/다음 달 날짜 흐리게 |
| **주** | 시간축(세로) × 요일(가로). 종일 이벤트 상단 별도 행. 현재 시각 선 |
| **일** | 단일 열 시간축 |
| **일정표(Agenda)** | 날짜별 그룹 리스트. 날짜 헤더 + 이벤트 행 |

- 상단 내비게이션: **이전 / 다음 / 오늘 / 기간 라벨(클릭 시 연·월 선택기 모달)**.
- 뷰 전환은 세그먼트 버튼. 모바일에서는 드롭다운으로 축약.

### 5-3. 모듈 사이드바 (3블록 + 구분선)

1. **미니 달력** — 월 이동 헤더, 날짜 셀, **이벤트 있는 날 점 표시(카테고리 색)**, 날짜 클릭 시 그날 이벤트 팝오버
2. **캘린더 목록** — 항목별 색상 점 + 이름, 체크/선택으로 필터, 항목 우측 더보기 메뉴(수정/삭제), 목록 제목 우측 `+` 버튼
3. **카테고리 목록** — 아이콘 + 색상 + 이름 + 개수, 동일한 필터/메뉴/추가 구조

각 블록에 **빈 상태 문구**가 따로 있다. 예: "카테고리를 찾을 수 없음 / 위의 더하기 버튼을 클릭해 생성하세요."

### 5-4. 이벤트 블록 & 상세

- **이벤트 블록**: 카테고리 색 배경/보더 + 제목 + 시간. 높이가 아주 작을 때(15분짜리) 축약 규칙 필요.
- **호버 툴팁**: 제목, 시간, 위치 요약.
- **상세 팝오버/모달**: 헤더(아이콘·제목·카테고리 칩·액션) + 시간 + 위치 + 참조 링크 + 설명(서식 있는 텍스트) + 하단 액션(수정/삭제/"참조 보기").
- 이벤트는 **드래그로 이동, 가장자리 드래그로 시간 변경** 가능 → 드래그 중 상태 디자인 필요.

### 5-5. 이벤트 생성/수정 모달 (모듈 폼의 대표 사례)

입력 필드 조합 — **이 폼 하나가 공용 입력 컴포넌트 대부분을 소환한다.**

- 제목(텍스트), 유형 선택(**단일 / 반복**), 캘린더 선택, 카테고리 선택(아이콘+색상 포함 드롭다운)
- 시작·종료 일시(날짜+시간)
- 위치(검색형 입력, 지도 사용 토글)
- 참조 링크(URL), 설명(여러 줄, 서식)
- **반복 규칙 빌더** — 가장 복잡한 폼:
  - 빈도: 매시간 / 매일 / 매주 / 매월 / 매년
  - 빈도별 하위 입력: "매 N주, [월화수목금토일] 선택", "매월 특정 날짜 vs 첫째/둘째/…/마지막 + 요일", "매년 특정 날짜 vs 상대 요일"
  - 종료 조건: 없음 / N회 후 / 특정 날짜
  - 지속 시간: 숫자 + 단위(분·시간·일·주·개월·년)
- **반복 이벤트 편집 시**: "이번만 예외로 처리" 확인 모달 필요.

### 5-6. 부가 생성 경로 (AI · 외부 연동)

- 생성 버튼은 **드롭다운**: "직접 입력" / "이미지에서 스캔"
- **이미지 스캔 모달**: 파일 업로드(이미지·PDF) → 처리 중 → 인식 결과가 채워진 생성 모달로 자동 전환. 실패 토스트.
- 모달 헤더에 **AI 표식**이 붙는다(AI 사용 화면임을 표시).
- **외부 캘린더 구독(ICS)**: URL 입력 모달, 목록에 "마지막 동기화 시각" 표시, 동기화 중 상태.
- AI 키/지도 키가 없으면 → 해당 진입점 비활성 + 안내 툴팁. **핵심 기능은 그대로 동작.**

### 5-7. 위젯 2종 (대시보드용)

| 위젯 | 내용 | 상태 |
|---|---|---|
| 미니 캘린더 | 축약 월 달력 + 이벤트 점 표시 | 로딩 / 정상 |
| 오늘의 이벤트 | 오늘 일정 리스트, 항목 클릭 시 상세 | 로딩 / 정상 / **빈 상태("오늘은 일정이 없습니다")** |

위젯은 껍데기 사이드바 축소 여부에 따라 폭이 변한다 → **가변 폭 대응 필수.**

### 5-8. 모듈 간 연동 (중요)

캘린더는 **다른 모듈의 데이터를 자기 카테고리처럼 표시**한다.

- 할 일 모듈 설치됨 → "할 일 마감" 카테고리가 자동 생성되어 캘린더에 표시(빨강, 전용 아이콘)
- 영화 모듈 설치됨 → "영화" 카테고리 자동 표시(주황)
- 해당 모듈 미설치 → **그 카테고리는 목록에서 사라짐**

→ 디자인 요구: **"내 것" 카테고리와 "다른 모듈이 꽂아준" 카테고리가 시각적으로 구분**되어야 하고(수정/삭제 불가), 목록 개수가 설치 상황에 따라 늘고 준다.

### 5-9. 이 모듈이 요구하는 공통 컴포넌트 (체크)

색상 선택 · 아이콘 선택 · 날짜/시간 · 반복 규칙 빌더 · 위치 검색 · 파일 업로드 · 드롭다운(아이콘 포함) · 태그 칩 · 컨텍스트 메뉴 · 확인 모달 · 빈 상태 · 툴팁 · 세그먼트 버튼 · 위젯 카드

> **새 모듈 명세를 쓸 때는 5-0 ~ 5-9의 항목을 그대로 채우면 된다.**

## 6. 모듈 표준 명세 — 예시: 할 일

> 캘린더가 **시각화형(그리드/캔버스)** 대표라면, 할 일은 **목록형(리스트/필터)** 대표다.
> 둘 다 §5의 5-0~5-9 틀을 그대로 쓴다 — 값만 다르다.

### 6-0. 모듈이 선언하는 것

| 항목 | 할 일의 값 |
|---|---|
| 표시 이름 | 할 일 |
| 아이콘 | 체크리스트 아이콘 |
| 카테고리 | 생산성 |
| 한 줄 설명 | "다시는 할 일을 잊지 마세요 (빨래는 예외일 수도)." — 캘린더와 같은 톤 |
| 화면 | 메인 화면 1개 |
| 위젯 | 1개 — 할 일 목록 |
| 외부 서비스 키 | 없음 (완전 오프라인 동작) |
| 다국어 | 4개 언어 (한국어 미포함 — 새 언어 추가가 흔하다는 뜻으로 참고) |

### 6-1. 메인 화면 레이아웃

목록형 모듈은 **모듈 사이드바가 "필터 패널"** 역할을 한다 — 캘린더의 "보기 대상 전환"과 달리 여기선 **상태/우선순위/리스트/태그 4단 필터**.

```
┌──────────────┬───────────────────────────────────────────┐
│ [모듈 사이드바]│  전체 작업 (12)          [필터 칩 나열]     │
│              │                              [+ 새 작업]   │
│  상태         ├───────────────────────────────────────────┤
│   · 전체 12   │  ▢ [●] 세금 신고하기                       │
│   · 오늘 3    │      기한: 2일 후          #재무 #긴급      │
│   · 예정 5    │  ──────────────────────────────────────   │
│   · 지연 1    │  ▢ [●] 화분 물주기                         │
│   · 완료 8    │      완료: 3시간 전                        │
│  ──────────  │  ──────────────────────────────────────   │
│  우선순위     │  ▢ 세탁물 찾기                             │
│   · 높음 2    │                                           │
│  ──────────  │                                    (FAB) │
│  리스트       │                                           │
│   · 업무 🔵   │                                           │
│  ──────────  │                                           │
│  태그         │                                           │
│   #긴급ㅤ#재무 │                                           │
└──────────────┴───────────────────────────────────────────┘
```

### 6-2. 헤더 & 필터 (뷰 전환 대신 "필터 조합")

캘린더는 뷰를 전환하지만, 할 일은 **필터를 겹쳐서 목록을 좁힌다.**

- 제목이 필터 상태에 따라 동적으로 바뀐다: 전체 작업 / 오늘의 작업 / 예정된 작업 / 지연된 작업 / 완료된 작업 / **필터링된 작업**(리스트·태그·우선순위 조합 시)
- 제목 옆 **결과 개수** 표시.
- **필터 칩 바**: 리스트/태그/우선순위를 다중 선택 칩으로 활성화. 칩 선택 시 헤더 제목도 같이 바뀜.
- 새 작업 버튼(데스크톱) / 햄버거로 모듈 사이드바 여는 버튼(모바일).

### 6-3. 모듈 사이드바 (4블록 + 구분선)

캘린더보다 한 블록 많다 — **상태 필터가 최상단에 추가됨.**

1. **상태** — 전체 / 오늘 / 예정 / 지연 / 완료. 각 항목에 **개수 배지**. 단일 선택(라디오 성격).
2. **우선순위** — 색상 점 + 이름 + 개수. 다중 선택 가능.
3. **리스트** — 캘린더의 "캘린더 목록"과 동일 패턴(색상 점 + 이름 + 더보기 메뉴 + `+`).
4. **태그** — 이름만 있는 단순 칩 목록(색상 없음). 태그는 색·아이콘이 없는 **가장 단순한 분류 단위** 예시로 참고.

### 6-4. 작업 항목 (리스트 셀)

- 카드형 한 줄: **왼쪽 색 바**(소속 리스트 색) + 제목 + 우선순위 점 + 하단 보조줄(마감일 or 완료 시각 + 태그 칩들) + **우측 체크박스**.
- 체크박스 토글 = 즉시 완료 처리(별도 확인 없음, 목록에서 바로 상태 반영).
- 항목 클릭(체크박스 제외 전체 영역) → 수정 화면 오픈.
- **마감 임박/지난 항목은 날짜 텍스트가 경고색**으로 바뀜. 완료 항목은 "완료: n시간 전"으로 문구 자체가 바뀜.
- 대시보드 위젯 안에서는 **같은 카드가 더 옅은 배경**으로 재사용(카드 컴포넌트의 variant 필요).

### 6-5. 작업 생성/수정 — 모달이 아니라 "드로어(Drawer)"

**캘린더와 다른 패턴**: 중앙 모달이 아니라 **화면 오른쪽에서 슬라이드 인**하는 전체 높이 패널. → 시안에 **모달 vs 드로어 두 오버레이 유형**이 모두 필요하다는 뜻.

- 헤더: 아이콘(생성/수정에 따라 다름) + 제목 + 우측 **컨텍스트 메뉴(삭제)**.
- 필드: 제목(텍스트, 필수) → 시간 포함 여부(토글) → 마감일(날짜/시간) → 우선순위 선택기(색상 점 드롭다운) → 리스트 선택기(색+아이콘 드롭다운) → 태그 선택기(다중 입력형) → 메모(여러 줄).
- 하단: 취소 / 생성·수정 버튼(전체 폭, 모바일에서 세로 쌓임).
- 삭제는 드로어 안 컨텍스트 메뉴 → **확인 모달**(드로어 위에 모달이 겹치는 조합 발생).

### 6-6. 리스트 · 우선순위 · 태그 생성 모달 (3종의 같은 패턴)

- **리스트 모달**: 이름 + 아이콘 선택 + 색상 선택 — 캘린더 "캘린더/카테고리 모달"과 완전히 동일한 필드 조합.
- **우선순위 모달**: 이름 + 아이콘 + 색상 (리스트와 동일 패턴, 개념만 다름).
- **태그 모달**: 이름만(아이콘·색상 없음) — **가장 미니멀한 생성 모달** 기준으로 참고.

### 6-7. 위젯 1종 (대시보드용)

| 위젯 | 내용 | 상태 |
|---|---|---|
| 할 일 목록 | 오늘 마감 작업 리스트, 체크박스로 바로 완료 처리 가능 | 로딩 / 정상 / **빈 상태("오늘 할 일 없음")** |

캘린더 위젯과 달리 **위젯 안에서 직접 상태를 바꾸는 조작(체크)이 가능** → 위젯이 읽기 전용이 아닌 사례로 참고.

### 6-8. 모듈 간 연동

할 일은 캘린더의 "연동받는 쪽" 사례다(§5-8 참고) — 할 일의 마감일이 캘린더에 자동으로 얹힌다. 할 일 화면 자체에는 다른 모듈 데이터가 들어오지 않음(단방향 연동 예시).

### 6-9. 이 모듈이 요구하는 공통 컴포넌트 (체크)

색상 선택 · 아이콘 선택 · 날짜/시간 · 체크박스 · 다중 선택 태그 필터 바 · 드롭다운(색상/아이콘 포함) · 태그 칩 · 컨텍스트 메뉴 · 확인 모달 · **드로어(패널형 오버레이)** · 빈 상태 · 위젯 카드(조작 가능형)

## 7. 공통 컴포넌트 인벤토리

**표시**

**레이아웃**

**내비게이션**

**피드백·오버레이**
모달 / **드로어(패널형 오버레이)** / 확인 모달 / 이미지 뷰어 / 컨텍스트 메뉴 / 알림 배너 / 토스트 / 로딩 화면 / 빈 상태 화면 / 에러 화면 / 404 화면 / 서버 연결 끊김 상태

**버튼 체계**
주요 / 보조 / 위험(삭제) / 텍스트형 / 아이콘 전용 / FAB / **드롭다운 분할 버튼**. 각각 기본·호버·활성·비활성·로딩 상태.

## 8. 상태 정의 (모든 목록/화면 공통)

1. **로딩** — 스켈레톤 또는 로딩 화면
2. **빈 상태** — 아이콘/일러스트 + 문구 + 첫 액션 버튼 (모듈마다 문구 다름 → 템플릿화)
3. **에러** — 원인 문구 + 재시도
4. **오프라인 / 서버 미응답** — 전역 배너 또는 전체 화면
5. **키·연동 미충족** — 안내 + 설정으로 이동, 기능 일부만 비활성
6. **검색 결과 없음** — 빈 상태와 별도 문구
7. **동기화 중** — 외부 데이터 갱신 표시

## 9. 전역 요구사항

| 항목 | 내용 |
|---|---|
| 반응형 | 데스크톱(사이드바 고정) / 태블릿(사이드바 축소) / 모바일(오버레이 사이드바 + FAB). **3단 레이아웃(껍데기+모듈 사이드바+콘텐츠)이 모바일에서 1열로 붕괴**하는 규칙 필수. |
| 다크 모드 | 전 컴포넌트 필수. 배경 이미지 + 다크 조합도 검증. |
| 다국어 | 한 라벨 길이가 언어마다 최대 2배 → **고정폭 라벨 금지**. |
| 접근성 | 명도 대비 AA, 키보드 포커스 링, 터치 타겟 최소 크기. **사용자 지정 강조색에서도 대비가 깨지지 않는 규칙** 필요. |
| 확장성 | 시안에 없는 모듈이 나중에 들어온다. **"이 컴포넌트로 무엇이든 조립 가능한가"** 가 판단 기준. |
| 아이콘 | 단일 선형 아이콘 세트. 모듈이 임의 아이콘을 고른다 → 일관성은 세트로 확보. |
| 사용자 색상 | 캘린더·카테고리처럼 **사용자가 항목마다 색을 지정**한다. 임의 색이 UI에 섞여도 무너지지 않는 색 사용 규칙(점·칩·좌측 바 등) 필요. |
